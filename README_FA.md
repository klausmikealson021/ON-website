# ORIGINAL NET | اسکلت صفحه اصلی - فاز اول

این بسته، نسخه آغازین صفحه اصلی سایت است. پروژه با Astro ساخته شده و خروجی آن HTML/CSS/JavaScript استاتیک خواهد بود. برای میزبانی اولیه به سرور اختصاصی یا دامنه پولی نیاز ندارید؛ می‌توانید مخزن GitHub را به Cloudflare Pages متصل کنید.

## ساختار فایل‌ها

- `src/pages/index.astro` : ساختار HTML صفحه اصلی و متن بخش‌ها
- `src/layouts/BaseLayout.astro` : چارچوب مشترک صفحه، عنوان، توضیحات و فونت‌ها
- `src/styles/global.css` : رنگ‌ها، ظاهر، واکنش‌گرایی، شیشه‌ای بودن هدر و جلوه‌های عمق/سه‌بعدی
- `src/scripts/main.js` : منوی موبایل، کنترل اسلایدر و پنجره اطلاعات همکاری
- `public/media/ASSETS_README_FA.md` : مشخصات فایل‌های ویدئویی و تصویری که بعداً باید در سایت قرار بگیرند
- `astro.config.mjs` و `package.json` : تنظیمات ساخت پروژه

## اجرای محلی در ویندوز

1. Node.js نسخه 22.12 یا جدیدتر نصب باشد.
2. پوشه پروژه را از ZIP خارج کنید.
3. در File Explorer وارد پوشه `original-net-homepage` شوید.
4. در نوار آدرس File Explorer بنویسید `powershell` و Enter بزنید.
5. این دستور را اجرا کنید:

```powershell
npm install
```

6. سپس اجرا کنید:

```powershell
npm run dev
```

7. نشانی‌ای که ترمینال نمایش می‌دهد (معمولاً `http://localhost:4321`) را در مرورگر باز کنید.

برای ساخت نسخه قابل انتشار:

```powershell
npm run build
```

خروجی آماده انتشار داخل پوشه `dist` ساخته می‌شود. پوشه `dist` را دستی در GitHub ویرایش نکنید؛ این پوشه در زمان ساخت Cloudflare تولید می‌شود.

## انتشار با GitHub و Cloudflare Pages

1. در GitHub یک مخزن جدید و خالی با نامی مثل `original-net-website` بسازید. گزینه افزودن README یا فایل اولیه را فعال نکنید تا مخزن خالی بماند.
2. فایل ZIP را در کامپیوتر Extract کنید.
3. وارد مخزن GitHub شوید و از `Add file` گزینه `Upload files` را انتخاب کنید.
4. **محتویات داخل پوشه** `original-net-homepage` را بارگذاری کنید، نه خود پوشه مادر را. در ریشه مخزن باید `package.json` و `astro.config.mjs` دیده شوند و پوشه `src` هم در همان سطح باشد.
5. تغییرات را با پیام `Initial homepage scaffold` ذخیره کنید.
6. در Cloudflare وارد `Workers & Pages` شوید، `Create application` و سپس `Pages` را انتخاب کنید و مخزن GitHub را متصل کنید.
7. تنظیمات ساخت را این‌طور قرار دهید:

| گزینه Cloudflare | مقدار |
|---|---|
| Production branch | `main` |
| Framework preset | `Astro` (اگر نمایش داده شد) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | خالی |

8. `Save and Deploy` را بزنید. بعد از موفقیت، سایت روی زیردامنه رایگان `pages.dev` منتشر می‌شود.

با هر بار ثبت تغییر جدید در شاخه اصلی GitHub، Cloudflare نسخه جدید را می‌سازد و منتشر می‌کند.

## مواردی که فعلاً عمداً نهایی نشده‌اند

- ویدئوی Hero و ویدئوهای دو کارت محصول هنوز فایل واقعی ندارند؛ محل آن‌ها در HTML/CSS رزرو شده است تا تا زمان آماده‌شدن مدیا، خطای فایل 404 ایجاد نشود.
- گوی ذرات فعلاً یک پیش‌نمایش سبک CSS است؛ شبیه‌سازی سنگین Canvas/WebGL و صدای تعاملی برای مرحله جداگانه نگه داشته شده است.
- هفت کارت تجربه مشتری، جایگاه خالی هستند. هیچ نظر یا امتیازی ساخته نشده است. فقط بعد از دریافت تجربه واقعی و اجازه انتشار، متن کارت‌ها را جایگزین کنید.
- سه کارت مطالب منتخب فعلاً موضوعات پیشنهادی‌اند، نه مقاله منتشرشده؛ لینک مقاله جعلی ایجاد نشده است.
- دکمه «مشاهده محصولات» و CTAهای مربوط به کانال از لینک دعوتی که مالک مشخص کرده استفاده می‌کنند. صفحه‌های مستقل Premium و Stars در مراحل بعدی ساخته می‌شوند.
- دکمه همکاری فعلاً یک پنجره اطلاعات اولیه باز می‌کند. صفحه مستقل قوانین همکاری، پس از نهایی‌شدن شرایط واقعی ساخته می‌شود.
- لینک شبکه‌های اجتماعی در دکمه مشاهده محصولات هنوز منو نیست؛ در فاز اول مطابق خواسته فعلی مستقیم به کانال تلگرام می‌رود.

## نکات فنی و ایمنی

- هیچ رمز عبور یا کد ورود تلگرام در فرم یا سایت درخواست نمی‌شود.
- بازشدن تلگرام، ارسال پیام یا ثبت قطعی سفارش محسوب نمی‌شود.
- حرکت‌های تزئینی با تنظیم `prefers-reduced-motion` کاربر محدود می‌شوند.
- چرخش خودکار اسلایدر تجربه مشتری تا زمان وجود حداقل دو نظر واقعی و تأییدشده فعال نمی‌شود.
- فونت‌ها از Google Fonts بارگذاری می‌شوند و برای نمایش آن‌ها به دسترسی مرورگر به سرویس Google Fonts نیاز است. در مرحله بهینه‌سازی می‌توان نسخه مجاز فونت‌ها را به‌صورت محلی میزبانی کرد.

## نکته مهم درباره نگهداری

فایل‌های `index.astro`، `global.css` و `main.js` بخش‌های جداگانه یک صفحه هستند. در مرحله‌های بعدی، هر بخش به کامپوننت مستقل تبدیل می‌شود تا تغییر دادن آن نیازمند دستکاری کل صفحه نباشد.
